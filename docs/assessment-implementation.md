# Consulting assessment workbench implementation

Approved user plan: provider-free, synthetic-data-only consulting assessment → investment decision workbench. Five surfaces: Brief, Evidence, Options & Value, Recommendation, Deliverables. Preserve the public two-project demo independently.

## Delivery tasks

1. Versioned domain, financial engine, assessment policies and synthetic factories. Unknowns stay null, options persist independently, cash and capacity remain separate.
2. Transactional IndexedDB repository, backup/restore, legacy migration and import preview. Reject stale writes and retain original legacy records.
3. Five-surface responsive client workbench, implemented in two reviewable slices: 3A shell/persistence/engagements/discovery/evidence; 3B alternatives/scenarios/recommendations/validation. The combined requirements remain in assessment-task-3.md.
4. Consistent Markdown, eight-slide PPTX and XLSX exports; regression, accessibility and browser journeys; deployment after full verification.

## Constraints

- No live AI, content transmission, hosted database, paid providers or confidential data.
- Keep Next.js/React/Zod/Decimal.js and current export libraries; no bulk dependency changes.
- USD/GBP/EUR per engagement, no FX conversion; 36 monthly cash flows relative to business as usual.
- Compare BAU, process/rules, AI assistance and broader automation; recommendations are advisory.
- Preserve existing demo records and legacy snapshots; no automatic removal of originals.
- Human practitioner validation requires external participants and cannot be claimed from automated tests.

## Preflight interface checks

| Producer → consumer      | Boundary                                   | Ruling                                                        |
| ------------------------ | ------------------------------------------ | ------------------------------------------------------------- |
| Domain → repository      | Workspace version, revision and validation | Domain schemas validate all loaded and imported records       |
| Economics → UI/exports   | Same model and conventions                 | One deterministic calculation implementation                  |
| Evidence → assumptions   | Reviewed source linkage                    | Reviewing evidence never automatically mutates numeric inputs |
| Policy → snapshot/export | Recommendation and source revision         | Snapshot persists; changes mark it stale                      |
| Storage → UI             | Transactional optimistic revision          | Save succeeds before UI claims persistence                    |
